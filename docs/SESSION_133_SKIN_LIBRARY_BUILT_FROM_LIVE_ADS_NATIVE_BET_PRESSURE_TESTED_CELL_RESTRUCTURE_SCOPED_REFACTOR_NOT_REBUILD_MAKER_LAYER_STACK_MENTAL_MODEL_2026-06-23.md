## Part 2 — The "go native" bet, PRESSURE-TESTED (it holds, honestly)

Two readers graded every claim behind "go native" as **[MEASURED]** (hard data) or **[DIRECTIONAL]** (consensus/inference).

- **🔴 The foundational truth:** *no audited per-format performance data exists anywhere* (verified 3 ways). Every strategic premise — ad-blindness ("3–5×" is an unsourced practitioner number), "creative is the new targeting," "native is the dominant trend" — is **[DIRECTIONAL]**. **The ₹20–30k beta is the only real judge.**
- **What IS measured:** native is **genuine white space** in ingestibles (zero founder-POV / review-screenshots in the audited top ads); **PAS is the active wave** (new + multi-variant vs the evergreen discount ads); the category already runs ~90% statics.
- **The leaps of faith:** "native converts better" (no data), **static ≈ video** (native UGC is strongest in *video*; we make statics — the likeliest assumption to bite), and "white space = opportunity (not unloved-for-a-reason)."
- **Conclusion (hold the direction):** keep going native, **for two reasons that don't need performance data** — (1) it's **measurably distinct** (on today's Meta, looking different *is* the targeting lever), and (2) it's the **one style where our AI-look isn't a liability** (native is *supposed* to look raw, so the "AI gloss" weakness goes invisible). It's a *smart bet, not a sure thing.*
- **Key reassurance:** the **skin × engine split is safe regardless** of whether native wins — separating "the look" from "the pitch" is a better factory for *any* formats. Only *which skins we fill first* is the native bet.

## Part 4 — The anti-genericness / anti-copy discipline (locked conceptually)

The user pushed on the right risk: *won't the model just copy these reference images?* The locked answers:

- **The skin library is OUR quarry, never model input.** The plan: the model **never sees these images** (it would clone the nearest surface). It reads **words** — the distilled *move* — not pictures.
- **The fake twin** = each skin names its own slop version (the "evil twin") so the **independent critic** can hunt and kill it. It's a *bad example in words, for the critic* — and at render time it flips to a **positive** instruction (renderers ignore "don't").
- **How genericness is countered (the 5 locks, from the S118 genericness conclusion):** (1) start sharp upstream (a specific Bet — ~80% of it); (2) build only from the brand's real material (the MAKER rule); (3) every skin/engine names its fake twin; (4) an **independent** swap-test critic (a model grading its own work blesses generic); (5) vision-check the render held the concept.
- **The native twist:** going native dodges the polished-AI-poster look, but opens **native-template slop** (every brand's fake-WhatsApp identical) — the swap test catches that too.

## Part 6 — The mental model, re-taught in plain language (keep for onboarding / teaching)

The user (correctly) kept catching jargon; the version that landed:

- **The one load-bearing idea:** *slop isn't the AI being uncreative — it's the AI being under-informed.* Left to guess, it reaches for the most average (= the category cliché). So the whole cell is two jobs: **put specifics in, or catch drift on the way out.**
- **The anatomy, plain ↔ real name ↔ file:**

| The story step | Real name | Lives in |
|---|---|---|
| the order (who/promise/proof) | **the Bet** | (from strategy, before the cell) |
| the playbook | the method | `SKILL.md` |
| pick the pitch + the disguise | **match → derive** | `SKILL.md` |
| what it says | **engine** | `engines/` |
| what it looks like | **skin** | `skin-grammar.md` |
| who took the photo | **maker** | `layer-stack.md` (a *fresh* per-ad decision, not a file) |
| the look + lettering | style / type | `style-grammar.md` · `type-grammar.md` |
| the locked-down build sheet | **shot spec** | `shot-spec.md` |
| the stranger + logo-swap | **critic + swap test** | `critic.md` |
| the boring-list | counterexamples | `counterexamples.md` |
| draw, then check | render + **vision gate** | `SKILL.md` |

- **The picture pipeline (the part the user drilled into), in order — all of it inside `layer-stack`:**
  > **skin** (the *kind* of picture) → **scene** (*where*, from the claim) → **maker** (*who shot it* — the keystone, step 3 not step 1) → **treatment** (the *feel*, from the brand) → **details** (the "sweep" — every element named)
  - **skin = the container; the claim = what goes in it.** (Same claim in a candid-photo skin → a 2am nightstand; in a chat-screenshot skin → no scene, the claim becomes the text thread.)
  - **claim owns** the *where* (scene) and the *who* (maker); **brand owns** the *feel* (treatment); **skin owns** the *kind*. None of them is the AI guessing.
  - **The maker is one-of-a-kind → that's why it's not a file.** Reusable things (the skin menu) are files; per-ad decisions (the maker, the filled build sheet) are made fresh.
