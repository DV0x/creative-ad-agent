## Detailed findings (one per cluster)

### Leak 1 — F1 / Cluster 3 / Wrong-brand redirect (Mamaearth)

**Where:** `agent/.claude/agents/research.md:22-34` (Step 1 "Extract Brand Name") + `:35-81` (Step 2 "Fetch Homepage") + `:217-225` (Rules)

**Quoted leak (offending behavior is what's NOT there):**

```
Step 1: Extract Brand Name
From URL, extract brand name for file naming:
https://www.theratefinder.ca/ → theratefinder
https://acme.io/products      → acme

Step 2: Fetch Homepage
WebFetch the homepage with this prompt:
Extract factual information from this homepage: ...
```

Rules at `:217-225` cover: be specific, extract colors, analyze ICP, exact quotes, note missing info, keep it concise. **No "verify landing"**, **no "detect redirect"**, **no "locale check"**, **no "halt on mismatch"**. The orchestrator (`cloudflare/sandbox/orchestrator-prompt.ts:33-34`) just passes the URL through with zero verification contract on either side.

**Output schema (`research.md:127-213`)** has a single `**URL:** [url]` line — agent fills with the input URL, NOT the resolved URL. So even if WebFetch followed a redirect, the brief shows the user-intended URL and the human never sees the swap.

**Why this produces the failure:** `WebFetch` silently follows HTTP redirects. `mamaearth.in` → `mamaearth.com` returns US brand content. Agent dutifully extracts US-brand facts and writes them to `mamaearth_research.md`. No mismatch signal anywhere downstream.

**Files needing change:**
- `agent/.claude/agents/research.md` — Step 1.5 (verify-landing), Resolved URL + Locale fields, halt-on-mismatch rule
- `cloudflare/sandbox/orchestrator-prompt.ts` + `server/lib/orchestrator-prompt.ts` — surface `brand_mismatch` to user as clarification turn
- (optional) `cloudflare/src/durable-objects/campaign-session.ts` — wire the clarification turn

### Leak 3 — F5 / Cluster 2 / Reference image ignored (Staging-Creat)

**Where:** `agent/.claude/skills/art-style/SKILL.md:151-198` (Step 2.5 "Build Reference Image Roster") is **structurally orphaned**.

**The gap:** Step 2.5 is in SKILL.md's "Multi-Style Output Flow." But each workflow file (14 of them) is self-contained — when the agent enters a workflow (e.g., `lifestyle-render-hybrid.md` Steps 1-7), the workflow's prompt template has slots for SCENE, PRODUCT, ENVIRONMENT, LIGHTING, TYPOGRAPHY — but **no `referenceImageUrls` slot and no reminder to call `mcp__refs__get_reference_images`**. Verified by `grep -niE "reference image|referenceImageUrls|uploaded (image|photo|reference)|user.?uploaded|mcp__refs"` across all 14 workflow files: **0 matches**.

**Runtime plumbing is intact:**
- `cloudflare/sandbox/nano-banana-mcp.ts:147,170,245` — production MCP correctly accepts `referenceImageUrls` and routes to fal `nano-banana-pro/edit` endpoint
- `cloudflare/src/lib/local-ai-runner.ts:116,150` — local dev MCP mirrors
- `cloudflare/src/durable-objects/campaign-session.ts:1023-1041` — file uploads → R2 → fal URLs → `## Reference Images` marker appended to `aiPrompt`

**The leak is upstream:** prompts.json has no `referenceImageUrls` field because the workflow that produced it never knew to populate one. MCP's `hasReferenceImages` check is `false` → text-to-image endpoint chosen → generic gym scene with no Optimum/Creat packaging.

### Leak 4 — F5 / Cluster 2 / No ref-upload gate for visual-first verticals (Ravila)

**Where:** `cloudflare/sandbox/orchestrator-prompt.ts:1-132` + `server/lib/orchestrator-prompt.ts:1-116`

**Two gaps:**
1. **No vertical detection** — orchestrator's "Style Keywords" block (L40-47) routes by user-specified visual style words, not by brand vertical. Nothing classifies brand as hospitality/real-estate/apparel.
2. **Reverse-only ref logic** — L49-79 (cloudflare) covers *consumption*: "if `## Reference Images` marker exists, do X." **Zero check in the reverse direction** — nothing prompts the user to upload references when the vertical demands them.

The only category-detection downstream is `agent/.claude/skills/art-style/SKILL.md:65-95` — a category→style preselection table. **Hospitality, real-estate, and "visual-first" are not in the table.** Hotels fall through to "General/Unknown."

**Why this produces the failure:** For Ravila, `activeFileIds.length === 0`, so the entire `## Reference Images` injection branch (`campaign-session.ts:1031`) was skipped. Prompt went straight to text-to-image with hook-bank phrases like "premium business hotel / quiet rooms / fast WiFi." Nano-banana hallucinated a generic luxury hotel. The orchestrator never said "STOP — hotels need real photos."

**Recommend gate at:** orchestrator system prompt, between Workflow step 1 (research) and step 2 (hooks). Pre-research is too early — the vertical is only knowable after `research_brief.md`.

**Why USD leaks into IN hooks:** No instruction + USD-only reference set → writer pattern-matches the "$547,500 mortgage" exemplar regardless of research locale signal.

### Leak 6 — F6 / Cluster 6 / Soft CTAs (Arjuninfra)

**Where:** `agent/.claude/skills/hook-methodology/SKILL.md:297-318` (Step 4 "CTA")

**Quoted offending content:**

```
**Action Verb + Implied Outcome**
- "Learn more"     → "See your options"
- "Apply now"      → "Get your answer"
- "Contact us"     → "Talk to someone who gets it"
- "Get started"    → "Find your lender"

The CTA should feel like the natural next step, not a demand.
```

**The table actively trains AWAY from imperatives.** `"Apply now"` is the WEAK side, replaced by curiosity-phrased `"Get your answer"`. For a real-estate brand (Arjuninfra) needing `Book Site Visit` / `Reserve Unit`, the skill literally rewards the opposite direction.

**No channel-fit rule.** Nothing distinguishes Meta scroll-CTA (`Shop Now`, `Book Tour`, `Get Quote`) from brand-mechanism CTA (`See your options`).

**No verb whitelist.** No length rule. No commerce-vs-lead-gen split. CTA field exists in output schema (L378: `**CTA:** [Action + outcome]`) but content is free-form prose. Validation checklist (L411-419) tests Traceable/Owned/Felt/Clear/Theirs — **none check CTA strength**.

**Why CTAs come out soft:** rubric optimizes for "natural next step, not a demand," downgrading direct verbs in favor of curiosity phrases. Writer produces consultative outputs that pass the rubric but fail an F6 grader scanning for imperatives.

### Leak 7 — Cross-cutting / Orchestrator framing

**Where:** `cloudflare/sandbox/orchestrator-prompt.ts:6` + `server/lib/orchestrator-prompt.ts:6`

**Current opening (both files):**

> "You coordinate a 2-agent + skills system that creates conversion-focused ads."

**Verdict:** Generic pipeline coordinator. Leans Type B by omission.

- **No audience.** Zero references to D2C founders, performance marketers, growth teams, advertisers, or media buyers.
- **Identity is plumbing, not judgment.** Agent thinks of itself as a router, not as someone who should reject bad output.
- **Success criteria are pipeline-shape, not quality-shape.** "Report completion with image URLs" / "Done! N ad creatives generated" — nothing about Meta-platform fit, scroll-stopping, conversion lift, shippability.
- **Rule 4 explicitly defers:** *"Trust skills — don't micromanage their creative process."* The orchestrator disclaims final judgment, but only the hook skill (`hook-methodology/SKILL.md`) names "Meta ads" and a performance frame. The performance-marketer DNA exists in one skill, never reinforced at the layer where final shipping decisions live.

**Recommended one-line rewrite:**

> "You are a performance marketer running paid social for D2C founders — your job is to ship Meta-ready ad creative that converts, by coordinating a research → hooks → art → images pipeline and rejecting any output that wouldn't survive a media buyer's review."

**Bonus finding (separate bug, track elsewhere):** `cloudflare/sandbox/orchestrator-prompt.ts` and `server/lib/orchestrator-prompt.ts` have **drifted**. Server is stale: missing per-slot indexing, `targetImageIndices`, `hookTypes`, one-call-per-image rule, and iteration semantics that prod relies on (Rules 6-7 in cloudflare). Local dev will behave differently from staging/prod until re-synced.

## Cross-cutting patterns the leak map exposes

1. **Workflow files are self-contained — they should remind the agent of upstream contracts.** Step 2.5 (ref roster) and locale-extraction live in SKILL.md but never get re-stated in the workflow templates that actually produce `prompts.json`. **Self-contained == orphaned.**

2. **Exemplars matter as much as rules.** The hook skill has zero locale instruction AND zero non-USD examples. Adding instruction alone won't fix it — the canonical example needs to change too.

3. **The CTA / Step 4 rubric is actively wrong**, not just incomplete. This is the only place where the fix is "delete + replace," not "add."

4. **The orchestrator owns nothing.** It coordinates, it doesn't gate. No vertical detection, no shippability rubric, no reject-and-retry. Every fix that requires *judgment at the seams between stages* has nowhere to live today.

5. **Plumbing for refs is intact end-to-end** (D1 → R2 → fal URL → MCP edit endpoint). The break is purely in the instruction surface — workflow templates have no `referenceImageUrls` slot.

6. **Framing is upstream of everything else.** The agent thinks it's coordinating a pipeline, not shipping creative for a paying D2C client. That single wording change is high-leverage because every downstream skill inherits the orchestrator's frame.

## Implications for Step 3 (structural redesign sketch)

The leak map confirms the Scenario B handoff-redesign hypothesis:

| Pipeline stage | Leak fix that lives here |
|---|---|
| Research | Resolved-URL + locale extraction (closes F1, sets up F2) |
| Orchestrator | Framing rewrite + vertical detection + ref-upload gate (closes F5-Ravila, opens framing-as-gate everywhere else) |
| Hook bank | Locale-aware input contract + non-USD exemplars + CTA table replacement (closes F2 + F6) |
| Art direction → image prompt | `referenceImageUrls` slot in every workflow + ban "no text overlay" / "10% text" language + Nano-Banana-renders-text preamble (closes F4 + F5-Staging-Creat) |
| Orchestrator (closing gate) | Pre-ship floor-rubric check before declaring "Done!" |

All 6 floor checks have a designated owner stage. None require a new pipeline component — every fix lives in an existing file.
