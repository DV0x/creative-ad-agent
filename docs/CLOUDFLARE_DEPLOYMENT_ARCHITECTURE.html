Cloudflare Deployment Architecture

All-Cloudflare production deployment for the Creative Ad Agent — Last updated 2026-02-28

01 Architecture Overview

Key Architectural Insight The Durable Object is the single coordination point. It owns both ends: the browser WebSocket and the Sandbox container. No cross-machine relay, no pub/sub, no EventEmitter. The SDK streams directly into the DO, which writes directly to the WebSocket. This collapses three processes into one actor.

03 Durable Object Design

CampaignSession

Each DO instance is identified by user ID — one DO per user handles all their campaigns.

Concurrency Model

Durable Objects are single-threaded JavaScript actors. Only one message is processed at a time. This eliminates race conditions between WebSocket messages and sandbox output. While awaiting chunks from execStream(), the DO can still receive WebSocket messages (like cancel or ping) — the runtime interleaves I/O awaits.

Hibernation

When no generation is running, the DO hibernates via state.acceptWebSocket(ws). The WebSocket stays connected, but the DO stops billing for compute. Incoming messages (generate, follow_up, ping) wake it automatically.

Connection Replacement

On reconnect: the DO closes the old WebSocket (code 4001), stores the new one, replays buffered events since lastEventId, and resumes forwarding if generation is still running.

How the DO Invokes the Sandbox

// Inside CampaignSession Durable Object

// 1. Get or create sandbox (lazy start)
const sandbox = getSandbox(this.env.SANDBOX, `user-${this.userId}`, {
  sleepAfter: 600,  // 10 min idle -> sleep
});

// 2. Mount R2 for persistent storage
await sandbox.mountBucket('creative-agent-storage', '/mnt/r2', {
  endpoint: `https://${this.env.CF_ACCOUNT_ID}.r2.cloudflarestorage.com`,
  provider: 'r2',
  prefix: `/users/${this.userId}/`,
});

// 3. Start agent-runner with streaming
const stream = await sandbox.execStream(
  'npx tsx /app/agent-runner.ts',
  {
    env: {
      ANTHROPIC_API_KEY: this.env.ANTHROPIC_API_KEY,
      FAL_KEY: this.env.FAL_KEY,
      PROMPT: prompt,
      SESSION_ID: sessionId,
      RESUME_SDK_SESSION_ID: sdkSessionId || '',
      HOME: '/mnt/r2',  // JSONL to $HOME/.claude/
    },
  }
);

// 4. Parse SSE stream
for await (const event of parseSSEStream(stream)) {
  if (event.type === 'stdout') {
    const sdkMsg = JSON.parse(event.data);
    await this.processSDKMessage(sdkMsg);
  }
}

JSONL Persistence via R2 FUSE Setting HOME=/mnt/r2 causes the SDK to write JSONL transcripts to /mnt/r2/.claude/projects/{hash}/{sdkSessionId}.jsonl. 05 Data Flow

5.1 Initial Generation

Browser sends WebSocket message
{ type: "generate", prompt: "...", sessionId: "abc-123" }
Worker routes to Durable Object
Verifies Clerk JWT → env.CAMPAIGN_SESSION.idFromName(userId)
DO creates campaign in D1
Status: "generating". Sends { type: "ack", campaignId, sessionId }
DO starts Sandbox + mounts R2
getSandbox() → mountBucket() → execStream("npx tsx agent-runner.ts")
Stream processing loop
system.init → save sdk_session_id to D1
tool_use "Task" → WS { type: "phase", phase: "research" }
tool_use "Skill" → WS { type: "phase", phase: "hooks" / "art" }
tool_use "Write" → WS { type: "file" } + save to D1
tool_use MCP → WS { type: "phase", phase: "images" }
tool_result images → WS { type: "image" } + save to D1
result → WS { type: "complete" } + D1 status = "complete"
All events buffered in DO memory
Sequential IDs for reconnect replay

5.2 Follow-Up / Resume

Browser sends follow_up
{ type: "follow_up", prompt: "...", campaignId: "camp_xyz" }
DO looks up sdk_session_id from D1
Same DO (same userId), retrieves session state
Wake/create Sandbox, mount R2
R2 FUSE mount restores JSONL access automatically
execStream with RESUME_SDK_SESSION_ID
SDK reads JSONL from R2, resumes conversation. Same stream processing.

5.3 Reconnection / Recovery

Browser reconnects (new WebSocket)
DO replaces WebSocket ref, closes old with code 4001
Browser sends subscribe with lastEventId
DO replays buffered events, sends subscribed

5.4 Cancellation

Browser sends cancel
DO kills sandbox process, updates D1 status = "cancelled"
Sends { type: "complete", message: "Cancelled" }

08 Image Pipeline

URL format is unchanged: /images/{sessionId}/{filename}. Worker proxies to R2 with immutable cache headers (max-age=31536000).

09 EventEmitter Replacement

Eliminated entirely The image-events.ts module, registerMcpSession(), resolveWsSessionId(), and unregisterByWsSession() are all removed. The DO parses SDK stdout directly — it already knows its own userId, sessionId, and campaignId. The existing processSDKMessage() fallback path (lines 532-596 in websocket-handler.ts) becomes the primary and only path.

13 Local Dev Story

# Terminal 1: Worker + DO + D1 + R2 (all emulated locally)
npx wrangler dev

# Terminal 2: Client dev server
cd client && npm run dev

wrangler dev provides local D1 (SQLite), local R2 (filesystem), local Durable Objects (in-memory), and hot reload.

Sandbox SDK does NOT work with wrangler dev R2 FUSE mount requires deployed infrastructure. For local development, the DO detects AI_BACKEND=local and runs the SDK directly in-process — same as the current ai-client.ts architecture. Zero Docker, same DX.

14 Migration Path

Phase 1: Data Layer (D1 + R2)

Create D1 database, apply schema, rewrite DB modules to async, create R2 bucket, migrate existing data.

Phase 2: Worker (API Routes)

Create Worker fetch handler, port REST routes (campaigns, assets, images, health), port Clerk auth.

Phase 3: Durable Object (WebSocket)

Implement CampaignSession DO, port WS message handling, port processSDKMessage(), event buffer, BlockBuilder.

Phase 4: Sandbox (AI Execution)

Build Docker image, implement agent-runner.ts, configure R2 FUSE mount, test end-to-end flows.

Phase 5: Pages (Frontend)

Deploy client/dist/ to Pages, configure custom domain, set up routing rules.
